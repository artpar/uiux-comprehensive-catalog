# Goal prompt: complete and deploy the UX learning and work platform

Transform the existing UX Patterns Guide into a complete, coherent professional UX platform that people return to for **learning, practice, live work, and reliable reference**. Implement the product in this repository, preserve its useful catalog and search entry points, and deploy the finished release to the existing `uxpatternsguide.com` GitHub Pages site after the review gate below. Carry the work through to a verified live release; a plan, prototype, empty lesson shells, or draft PR does not complete this goal.

## Product and content

Use `docs/UX_LEARNING_CURRICULUM.md` as the curriculum blueprint and `docs/UX_PLATFORM_SAMPLE_CASES.md` as editorial prototypes. Author and implement **all 20 lessons across the five capabilities**: understand experience quality; diagnose and frame problems; design and apply; test and improve; and practice professionally. Every lesson must contain a meaningful explanation of the concept or method, a worked example showing expert reasoning, misconceptions and limits, a guided decision with credible alternatives and response-specific feedback, an independent application in a different context with a reviewable artifact, skill-specific assessment criteria, and relevant source-backed references. Vary answer positions and require reasons; do not mistake recognition of a conspicuously complete option for judgment. Give testing lessons findings to interpret and require a revised interaction linked to those findings. Build a substantial final case. Use web, mobile, enterprise, voice, physical, service, and AI-assisted contexts throughout the path. The six samples are starting material to improve, not final pages to paste unchanged.

Make the other three modes real. **Practice** should let people revisit and try cases by skill or context, including appropriate feedback and progression. **Work** should provide at least three usable guided workflows that produce exportable or copyable outputs: a UX critique/problem statement, a research or usability test plan, and a design decision memo or state model. **Reference** should retain the existing 298 pattern entries, comparisons, lab, sources, and agent exports, with working search and contextual links into learning and work. Keep direct access for professionals who arrive with a specific question. Connect all four modes around the user's goal rather than presenting separate collections of links.

Fact-check teaching claims against primary sources and the catalog's source trail. Label fictional exercise data clearly. The local-transit case needs a realistic evidence packet and transit-domain review before publication; the cited UK Department for Transport study concerns international disruption, so application to local transit is an inference. If that review cannot be obtained, substitute a fully vetted capstone and keep the transit case unpublished. Do not claim that lesson completion certifies professional mastery.

## Experience and implementation

Design a clean, restrained professional journey. A first-time visitor can understand the offer and begin without registering; a returning learner sees a precise resume point; a working practitioner can reach a tool or reference immediately; someone arriving from search can get the answer they sought and discover relevant practice. Show honest progress based on instruction, practice, and artifacts. Handle skipped work, partial work, blocked or cleared storage, and returning after a gap. Use the existing Astro static architecture and GitHub Pages pipeline unless a demonstrated requirement makes a service necessary. Local progress and optional saved work are sufficient for this release; explain their device-local nature. Keep the newsletter and existing URLs, metadata, sitemap, and agent exports functional.

Implement keyboard access, clear semantics, mobile layouts, reduced-motion behavior, and understandable error and recovery states. Add privacy-conscious Umami events for learning, practice, work, reference transitions, completion, and resumption. Never send free-form answers, personal data, or the private Umami bearer token to analytics or client code. Update privacy text to match actual behavior.

## Release gate and definition of done

Work in reviewable stages, but continue until every mode and every published lesson is complete. Run the repository's existing checks and production build. Inspect the actual interface in a browser at desktop and mobile sizes and verify keyboard and storage-failure paths. Walk a new-user journey, a direct-entry pattern journey, a full lesson with feedback and transfer, a return visit, and each work tool. Use `docs/UX_PLATFORM_REVIEW_PROMPT.md` as an independent release review; fix all blocking findings and repeat the review where the fixes affect a journey.

Prepare a working preview, a content/source inventory, and a concise release report. Present the complete, reviewable result for editorial and production approval as the final approval step. Once approved, merge or push through the existing GitHub Pages workflow, confirm the deployment succeeds, verify the live domain and core journeys, and check that Umami receives the intended events without sensitive payloads. Report the live URL, what shipped, verification results, and any genuine remaining limitations. Success is a credible place to learn UX deeply, practice judgment, use tools during real work, and consult the reference library throughout a career—not merely higher pageviews, longer sessions, or streaks.
